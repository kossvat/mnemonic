# mnemonic - loop rules (для автономной петли)

Этот файл читают и Claude, и Codex. Правила для запуска mnemonic в петле
(loop engineering): агент сам берёт задачу, пишет код, проверяет, чинит, ревьюит.

## Verification (тот кто говорит "нет")
Перед ЛЮБЫМ коммитом обязательно зелёное:

    cargo fmt && cargo clippy --release --all-targets -- -D warnings && cargo test --release

Если не зелёное, это не "готово". Чинить до зелёного или пометить BLOCKED.

## Loop policy
- Один пункт `specs/TODO.md` за тик, ничего лишнего сверху.
- Зелёная проверка: коммит понятным сообщением + отметить пункт `[x]`.
- Падает 3 раза подряд с той же ошибкой: пометить BLOCKED + причина, перейти к следующему.
- Потолок: максимум 5 пунктов за прогон, потом стоп и показать итог.
- Code review: после коммита прогнать `codex review --commit HEAD`, учесть замечания, при необходимости ещё тик.

## Codex model routing (GPT-5.6, verified 2026-07-10)
Модель под сложность выбирает агент сам, без вопросов:
- **Terra** = дефолт (`~/.codex/config.toml`: `model = "gpt-5.6-terra"`): рутинные ревью небольших диффов, повторные раунды после точечных фиксов, доки.
- **Sol** = сложное: `codex review ... -c model="gpt-5.6-sol"` / `codex exec -m gpt-5.6-sol`. Когда: архитектура, конкурентность/асинхронщина, security-чувствительный код, миграции данных/схем, большие диффы (~500+ строк), финальный gate-раунд перед деплоем/пушем крупной фичи.
- Паттерн: первый раунд большой фичи = Sol; раунды по съёжившимся диффам = Terra; контрольный финал = снова Sol.
- **Luna** не использовать. Сомневаюсь = Terra, эскалация на Sol при слабом/пустом ревью на нетривиальном диффе.

## Guardrails (НЕ делать без явной команды Свята)
- НЕ пушить (ни origin, ни mnemonic-public). Push только по команде.
- НЕ бампать версию в `Cargo.toml`.
- НЕ менять публичный API без явной пометки в итоге.
- При сомнении: стоп и спросить, а не "коммит-и-молиться".

## Commit style
Imperative, английский, короткие ("Add X", "Fix Y").
